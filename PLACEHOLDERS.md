# Placeholder images

Every file in `public/assets/_placeholder/` is a **development stand-in** and
must be replaced before production.

## What these actually are

They are **original schematic drawings**, generated by
[`scripts/make-placeholders.mjs`](scripts/make-placeholders.mjs) and rendered to
PNG with sharp. Regenerate them any time with:

```bash
npm run placeholders
```

No third-party photography was copied into this repo. The reference site's
images are licensed to that company, so using them — even temporarily — was
avoided entirely. Each placeholder is a labelled line drawing on a blueprint
grid, stamped **"PLACEHOLDER — NOT FOR PRODUCTION"**, so it is impossible to
mistake for finished artwork in a screenshot or a file listing.

The four `explainer-*` files are deliberately accurate: their geometry matches
the numbered hotspot coordinates in `content/solutions.ts` and
`content/services.ts`, so the annotated figures genuinely explain something even
while they are stand-ins. **When you replace them with photographs, re-check the
hotspot `x`/`y` percentages** — they are positioned against these drawings.

## The safety net

`npm run prebuild` runs [`scripts/check-placeholders.mjs`](scripts/check-placeholders.mjs):

- **Vercel production build** → fails while any placeholder remains.
- **Preview / local build** → passes with a warning, so the client can review.
- Override (not recommended): `ALLOW_PLACEHOLDERS=1 npm run build`
